# 自动更新发布流程

## 一、概述

从 v0.1.1 开始，AI提示词资产管家支持通过 GitHub Releases 自动检查更新。

- **v0.1.0**：不支持自动更新（需手动下载安装包）
- **v0.1.1 及以后**：支持手动检查更新 → 自动下载 → 安装重启

## 二、密钥管理

### 已生成的密钥

| 类型 | 位置 |
|------|------|
| 私钥 | `C:\Users\胡荣\.tauri\prompt-asset-manager` |
| 公钥 | `C:\Users\胡荣\.tauri\prompt-asset-manager.pub` |

公钥已写入 `src-tauri/tauri.conf.json` → `plugins.updater.pubkey`。

### ⚠️ 私钥安全规则

1. **私钥绝对不能提交到 GitHub**
2. **私钥绝对不能写入项目文件**
3. **私钥绝对不能打包进软件**
4. 如果私钥丢失，已安装的用户无法再接收新更新

### 备份私钥建议

将 `~/.tauri/prompt-asset-manager` 文件备份到安全位置（如密码管理器、加密 U 盘）。

## 三、每次发布流程（方案 A：本地打包 + 手动上传）

### 步骤 1：同步版本号

三处版本号必须一致：

- `package.json` → `"version": "0.1.x"`
- `src-tauri/Cargo.toml` → `version = "0.1.x"`
- `src-tauri/tauri.conf.json` → `"version": "0.1.x"`

### 步骤 2：设置签名环境变量

**Windows PowerShell：**
```powershell
$env:TAURI_SIGNING_PRIVATE_KEY = Get-Content "$env:USERPROFILE\.tauri\prompt-asset-manager" -Raw
```

**Windows CMD：**
```cmd
set /p TAURI_SIGNING_PRIVATE_KEY=<%USERPROFILE%\.tauri\prompt-asset-manager
```

**Git Bash：**
```bash
export TAURI_SIGNING_PRIVATE_KEY=$(cat ~/.tauri/prompt-asset-manager)
```

### 步骤 3：构建

```bash
npm.cmd run build
```

### 步骤 4：确认产物

构建完成后，检查以下文件：

| 文件 | 路径 |
|------|------|
| NSIS 安装包 | `src-tauri/target/release/bundle/nsis/AI提示词资产管家_0.1.x_x64-setup.exe` |
| 签名文件 | `src-tauri/target/release/bundle/nsis/AI提示词资产管家_0.1.x_x64-setup.exe.sig` |
| updater JSON | 由 GitHub Release action 生成或手动创建（见下方） |

### 步骤 5：创建 latest.json

在项目根目录创建 `latest.json`：

```json
{
  "version": "0.1.x",
  "notes": "更新说明：\n- 新增XXX功能\n- 修复XXX问题",
  "pub_date": "2026-05-28T00:00:00Z",
  "platforms": {
    "windows-x86_64": {
      "signature": "CONTENT_OF_.sig_FILE",
      "url": "https://github.com/OWNER/REPO/releases/download/v0.1.x/AI提示词资产管家_0.1.x_x64-setup.exe"
    }
  }
}
```

将 `.sig` 文件的**全部内容**填入 `signature` 字段。

将 `OWNER` 替换为你的 GitHub 用户名，`REPO` 替换为仓库名。

### 步骤 6：上传到 GitHub Release

1. 在 GitHub 仓库页面点击 **Releases** → **Create a new release**
2. Tag 版本号：`v0.1.x`（注意前缀 `v`）
3. Release 标题：`v0.1.x`
4. 上传以下文件：
   - `AI提示词资产管家_0.1.x_x64-setup.exe`
   - `AI提示词资产管家_0.1.x_x64-setup.exe.sig`
   - `latest.json`
5. 点击 **Publish release**

### 步骤 7：更新 tauri.conf.json 中的 endpoint

在 `src-tauri/tauri.conf.json` 中，将 `OWNER` 和 `REPO` 替换为实际值：

```json
"endpoints": [
  "https://github.com/你的用户名/你的仓库名/releases/latest/download/latest.json"
]
```

## 四、GitHub 仓库准备

1. 创建 GitHub 仓库（如 `prompt-asset-manager`）
2. 将项目代码推送上去
3. 首次发布时手动创建 v0.1.1 Release

## 五、测试更新

### 测试流程

1. 安装当前版本 v0.1.1
2. 修改三处版本号到 v0.1.2，做一个小改动
3. 设置 `TAURI_SIGNING_PRIVATE_KEY` 环境变量
4. 运行 `npm.cmd run build`
5. 上传 v0.1.2 安装包 + .sig + latest.json 到 GitHub Release
6. 打开 v0.1.1 软件 → 切到「🔑 API设置」→ 点击「检查更新」
7. 应发现 v0.1.2 → 点击「下载并安装」
8. 重启后版本为 v0.1.2
9. 检查本地模板库数据仍然完整

## 六、方案 B：GitHub Actions 自动发布（后续）

```yaml
# .github/workflows/release.yml
name: Release
on:
  push:
    tags: ['v*']
jobs:
  build:
    runs-on: windows-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: '22' }
      - run: npm install
      - name: Build
        env:
          TAURI_SIGNING_PRIVATE_KEY: ${{ secrets.TAURI_SIGNING_PRIVATE_KEY }}
        run: npm run build
      - uses: softprops/action-gh-release@v2
        with:
          files: |
            src-tauri/target/release/bundle/nsis/*.exe
            src-tauri/target/release/bundle/nsis/*.sig
```

使用时需要在 GitHub 仓库 Settings → Secrets 中添加 `TAURI_SIGNING_PRIVATE_KEY`。

## 七、重要提醒

1. **旧版 v0.1.0 不能自动更新** — 必须先手动安装一次 v0.1.1
2. **不要丢失私钥** — 丢失后需重新生成密钥并发新版本
3. **Windows 代码签名 ≠ Tauri updater 签名** — 没有 Windows 代码签名证书时用户会看到 SmartScreen 提示，但不影响 updater 功能
4. **本地数据不受影响** — 更新不会清空 localStorage 中的模板库和设置
5. **更新失败不回退** — 如果更新失败，需手动下载安装包覆盖安装
